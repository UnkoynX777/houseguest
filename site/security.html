Security and limitations

The source is public. Security rests on Windows access control, authenticated IPC and cryptography, not on secrecy.

WhoWhat Houseguest guarantees
Standard user, window closedRules keep applying. The service, its data and settings cannot be stopped, read or edited without administrator rights. Renaming an executable does not bypass hash or publisher rules. PIN guessing is rate limited.
Guest during a sessionThe session ends on time. Allowed programs cannot change policy.
Local administratorTampering is detectable. Removal and recovery are always possible, by design.
Physical accessNothing. Use BitLocker and a firmware password.

Hardening

  • Service runs as LocalSystem with a protected data folder and an HMAC-signed, atomically written state.
  • Authenticated named pipe with an explicit access list; caller identity comes from the pipe token.
  • Hash-chained audit log; PBKDF2-SHA256 PIN with persistent back-off.
  • The uninstaller refuses to run during an active guest session unless an administrator overrides it.
  • Fuzz targets for policies, globs, state and the command handler, AddressSanitizer builds, CodeQL, clang-tidy and dependency review in CI. Short fuzz runs found no issues; this is not an independent audit.

Known limits

  • Enforcement is reactive: a blocked program can run briefly.
  • Programs you allow can launch other programs.
  • Verified only on Windows 10 Pro 22H2; other editions and modified builds are untested.
  • Builds are not code signed yet.
